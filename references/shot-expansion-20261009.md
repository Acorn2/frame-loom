# 镜头扩充：横竖屏操作与数据表达

## 范围与决策

新增 type-and-filter、ai-stream-response、unit-dot-regroup 三项，覆盖六套当前风格与16:9／9:16；原有专用场景保留横屏边界，semantic-default 保留横竖屏。当前共40个场景，竖屏可选4个场景。既有48项筛选清单保持原口径，新三项单独记录，不改变48/48的含义。

输入 → 严格 schema → 显式阶段与内容校验 → 静态 renderer → 两种画幅的文本预检 → 实际样片与QA沿用同一生产链。点阵以独立入口补充 chart-live 家族中的未接入表达，不复用其不相容的槽位。来源固定 video-shotcraft commit 5ddbf521038b0a7accfb6dc1e0a9eb29c67277ab，独立实现，不复制上游素材、固定文案或新增依赖。

竖屏单独编排：搜索单列、任务上下文字、点阵纵向分组。配方库按风格与画幅读取实际样片；缺失时不借用横屏样片。竖屏项目配色沿用原限制，未扩展为支持来源配色。旧分镜与精确镜头版本解析不迁移。

## 验收条件

- 三项均可经过选择、初始化、schema、编译、预检和实际渲染。
- 搜索不匹配、时序倒置、未完成任务、数字不一致、非整数或超量点阵在渲染前拒绝。
- 六风格×两画幅均检查文本、安全区、字幕对比度与完整视频解码。
- 基础语义配方增加真实竖屏样片；库页面按当前画幅展示卡片和详情。

## 实际验证

- `npm run typecheck`、`npm run lint`、`npm run validate:shots` 均通过；目录核对40个场景、9个辅助动作、5个转场及原有48/48清单。
- 完整测试以 `npm run test -- --maxWorkers=2 --testTimeout=15000` 运行：29个文件、475项通过。修正详情面板的竖屏尺寸后再次运行配方库54项测试通过。新增27项测试覆盖六风格×两画幅、Unicode输入、严格时序、单位数量、确定性、边界及初始化选择。
- `npm run preview:library` 生成360份当前有效的实际renderer样片；`npm run preview:fonts` 更新30份字体组合样片。新增三项的36份风格×画幅样片均通过FFmpeg完整解码，确认30fps及960×540／540×960尺寸。
- `npm run build:library -- --require-previews` 完整预览构建通过；最终 `npm run check:docs` 核对246份Markdown与750个本地链接，`git diff --check` 通过。
- 标准 `render:storyboard` 与 `qa:storyboard` 链路以fast、visual-preview运行六份新配方原分辨率样例，覆盖1920×1080与1080×1920。六份自动QA全部通过，140个必选检查帧已查看，包含输入、筛选、点击、任务完成及点阵分组／柱形／汇总阶段。
- 本地库实际浏览器检查横竖屏切换、4项竖屏兼容集合、实际竖屏视频来源及桌面／390×844手机详情布局；手机播放控件位于可视范围，页面没有水平溢出。
- 机器可读的验证摘要和来源指纹见[验证记录](../examples/shot-recipes/expansion-review/verification.json)。样例分镜、来源说明与复现命令长期保存在项目内，不依赖临时渲染文件。

三项保持experimental。自动QA与必选帧复核不等于创作者完整播放批准，本轮未创建发布／交付批准，也未调用在线TTS。新配方均为内容驱动的界面示意，不承诺复刻真实产品界面；点阵仅接收合计1–120的整数单位。原有专用镜头未批量适配竖屏，竖屏来源配色仍保持原能力边界。
