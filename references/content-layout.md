# 内容优先布局与实际渲染检查

新建 2.4 项目默认声明 `layoutPolicy: "content-first-v1"`。这是独立于风格、字体和镜头版本的显式布局契约；没有此字段的旧分镜保持原渲染路径，2.1–2.3 不接受该字段。未知策略失败，不回退。已有项目采用此策略时须重新渲染、QA 和审核，不能沿用旧批准。

## 布局职责

`src/layout/scene-layout.ts` 定义内容、安全区、标题、正文、结论和字幕预留。原生媒体镜头使用侧边说明与完整高度的媒体区；图解使用紧凑标题与更大的正文区；短标题镜头保留自己的构图。专用镜头保留内部布局和运动，通过共享外壳使用统一内容边界。不同镜头不要求同一构图或相同字号。

`contain` 的实际图片尺寸由源图片比例和显示区共同决定，不能将 img 元素外框当成可见图片。占比只作复核线索，不强制所有素材达到统一百分比，不拉伸图片，不自动裁掉产品控件。`cover`、局部聚焦和图中小字仍须人工检查来源与关键区域。

关系节点按正文空间、分支数量及方向排布。风格装饰不能造成节点遮挡；内容过长时拆场或缩短有来源的文案，不以持续漂移或装饰动画规避检查。

## 生产检查

- `validate:storyboard`、`produce`、渲染和 QA 共用布局预检。连续四场使用同一实际布局结构时提示复核，允许有依据的连续比较；不得通过更换配方名称消除提示。
- 正式渲染在同一 Chromium、已加载字体及图片下采集入场中段、完成态、交接前及相邻重叠边界。检测生成文字与节点的实际位置、可见遮罩和图片 object-fit 后的尺寸。
- 中文标题按词换行，同一标题的词保留共同文字块身份；旋转文字的相邻词不因外接矩形交叠被误判成独立对象碰撞，逐词裁切仍逐一检查。
- 完成态的关键文字裁切、文字碰撞、独立节点遮挡阻止候选 MP4 发布，保留旧输出。动作中段的问题作为警告复核；跨场转场的短暂重叠不等于单场节点碰撞。
- 图片显示面积显著低于按该源比例可实现的面积时提示主体过小。此指标不推断截图内部文字、模型或控件是否清楚，不能代替查看原图和成片。
- 布局实测进入视频 `.render.json` 的 `profile.layoutQa`，绑定分镜哈希、生产锁和视频字节。QA 要求必选帧齐全；缺少证据不能声称检查通过。
- 全片播放、字幕可读性、内容推进、截图内部文字、源图片关键区域和音频质量仍需人工复核。自动 QA 不批准交付。

Agent 在 `shot-map.md` 记录逐场主体、需要读的区域、素材比例与完整/局部展示选择；检查每种实际布局和有变化的相邻镜头。TTS 改时后重复检查，不能只审一张代表图。

## 回归入口

```bash
npm test
npm run typecheck
npm run lint
npm run validate:shots
npm run test:content-layout
npm run test:content-layout -- --all
npm run test:content-layout -- --only pill-slot-cycle,word-roll
```

默认实际渲染回归覆盖所有当前横屏镜头、原生布局在六套风格下的样例、当前竖屏样例以及宿主动作和换章样例。`--all` 检查完整公开风格矩阵；回归素材与报告位于被忽略的 `.tmp/content-layout-regression/`，不是用户生产交付物。使用来源明确的公开演示素材，不调用 TTS、不发布内容。
