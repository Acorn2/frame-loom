# 根据文档选择和编排镜头

网页默认导出自动选择指令，不读取文档。Agent 在本地读取真实原文与素材后完成推荐；CLI 只校验兼容性和契约，不代替语义判断。用户可以改为手动集合，既有手动选择保持严格边界。

## 一次完成推荐与制作

1. 提炼观众需要理解的少数主张，保留各自主张的原文位置。先确定观看目的，再选择要讲的内容。
2. 为每场确定表达任务：主张、并列组成、先后步骤、差异、层级、真实数据或来源媒体。
3. 查询 `list:shots -- --style <id> --canvas <orientation>` 并读取候选配方。按任务选择互补的集合，不按网页分类凑齐，不设最低配方数量。同一基础配方可以承担不同语义画面，多个标题动画也可能仍是同一种表达。
4. 将逐场来源、主张、画面内容、关系、配方 ID/版本、理由、素材需求和关键提示写入 `shot-map.md`。自动选择完成后，初始化时显式传入 `--shots`，最终 `shotRecipes` 固定这次选定的集合。派生解析计划不作为可编辑输入。
5. `fast` 简要展示组合和理由后直接完成制作；`review` 把组合与讲稿、分镜、时长一起交给创作者审核。自动推荐不增加独立确认门槛。

| 文档中的内容 | 应有的画面工作 | 可考虑的配方 |
| --- | --- | --- |
| 一句主题或结论 | 建立短主张 | paper-title |
| 并列功能或概念 | 逐项展示组成 | list-reveal、concept-matrix |
| 操作步骤、生命阶段 | 真实顺序随讲解推进 | semantic-default 的 sequence |
| 选项或访问规则差异 | 同维度对照 | compare-reveal |
| 主体与分支或层级 | 显示来源支持的连接 | network-expand、diagram-cascade |
| 有口径和来源的数量 | 展示数值与比较 | semantic-default 的 metric、particle-sand-fill |
| 用户提供的真实界面 | 展示可追溯本地素材 | semantic-default 的 media |

以上是任务映射参考，不是通用固定套餐。生命阶段不等于带日期的时间线，类别数量不等于增长曲线，相关性不等于因果。产品介绍没有实拍素材时可用文档图解，但不能把图解称为真实操作演示。

## 手动集合

手动选择是白名单，不自动添加基础回退或任何未选配方。只有标题配方时，先明确其适用范围及长篇字卡风险；短标题片可以继续。原文所需的流程或对比无法在集合内表达时，说明具体缺口并请求扩大集合，不把缺口藏进长旁白。用户已明确坚持单一表达时记录取舍，在授权范围内继续。

## 渲染前内容检查

- 正文里的关键对象、步骤、差异、数字是否有对应可见内容，而非只写在旁白和底部字幕？
- 多场是否重复相同构图？重复是为了比较、连续讲解还是由可用集合限制？在 `shot-map.md` 说明必要重复。
- 动作是否跟随讲解？不要把所有内容在开头一两秒全部展开，之后只等待旁白结束。
- 最终完整态是否有足够阅读时间？有意义的阅读停留可以保留；不要通过持续漂移、换色或无关转场制造变化。
- 产品功能是否需要真实演示才能支持？素材不足时缩小画面主张，并保留事实边界。

`validate:storyboard`、`produce` 与 QA 共用内容警告：对至少 30 秒且至少 4 场的 2.4 分镜，80% 以上场景使用同一配方与语义类型时提示复查；只有 label 的 statement 场景，末动作后至少 5 秒且占场景至少 60% 时提示标题长停留。不同语义类型的 semantic-default 不视为同一构图。这些阈值是排查线索，不能自动判断内容正确或观看质量，不是拒绝渲染或批准交付的条件。

Agent 必须检查并解决实际表达缺口，或记录合理保留原因；自动 QA 成功不代表视频有足够的信息推进。TTS 实测改时后再次检查，完整播放复核仍然必要。

## 操作与单位构成

检索/选取的因果过程可用 type-and-filter；摘要、任务和完成回执可用 ai-stream-response；1–120个精确单位的分组统计可用 unit-dot-regroup。三项支持横屏和竖屏，须读取对应配方的来源、数量、状态与阶段边界；示意图不替代真实操作证据。不要把普通并列清单改写成已经完成的任务。大量数据不缩放成无依据的个体点数。

## 实际布局与素材适配

新2.4项目默认启用[内容优先布局](content-layout.md)。逐场记录主体、必须辨认或阅读的区域、原图比例及完整/局部展示选择。检查 object-fit 后的实际图片尺寸，不用素材容器占比代替主体占比。逐类检查标题、正文、关系节点和字幕边界，并检查实际相邻镜头的尺度变化与交接；TTS改时后重复。静态截图只能支持该状态，过程主张需要来源支持的连续变化。生成文字/节点的硬错误由实测拦截，图中小字与语义质量由Agent和完整播放复核。
