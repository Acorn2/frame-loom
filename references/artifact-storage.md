# 生产产物与空间管理

[文档导航](README.md) · [生产管线](production-pipeline.md) · [资源保护](../SECURITY.md#本地产物与资源保护)

视频生产的可重建检查图片不应随每次修订整套复制。原始文档、素材、采用的音频、分镜、候选视频、渲染记录、生产锁及审核记录需要保留；缓存和逐帧检查图具有不同的生命周期。

## 新审片包

`extract:review-frames` 和生产 QA 默认输出原分辨率、高质量 JPEG（FFmpeg `q:v=2`、4:4:4），联系图也使用 JPEG。字体、素材、透明 PNG 和正式封面不转换。检查细小文字或像素细节时可以从保留的视频按索引时间单独提取 PNG；JPEG 为有损检查副本，不能用作逐像素回归基准。

`review-frames.json` 保留所有检查点标签、必选属性及分页映射。落在同一实际帧的检查点共用一张图片；联系图仍按检查点顺序展示。通过索引的 `file`、`pages` 和 `contactSheets` 读取图片，不拼接固定的 `.png` 路径。1.1 索引额外记录实际帧号、原请求时间、媒体 SHA-256、唯一图片数及总字节。

图片使用含内容摘要的文件名，先生成完整包，最后替换索引。抽帧、分页或预算检查失败时保留旧索引及其图片。成功后只清理上一个 1.1 索引登记、摘要匹配且新索引不再使用的本工具 JPEG；不自动迁移或删除旧 PNG、未知文件及被外部修改的文件。

单次包中原图与联系图合计最多 **128 MiB**，超过后停止，不以减少必选事件覆盖、缩小原图或绕过 QA 继续生产。应先检查异常画面或拆分项目。48 是每页联系图的检查点数上限，不是全片检查点上限。

## 修订归档

在替换当前输入或固定名视频前运行：

```bash
npm run archive:revision -- projects/<id> before-caption-change
```

命令以项目生产锁保护快照，拒绝活动的 TTS 锁、音频发布事务、未处理的渲染事务、来源符号链接、越界路径与已有目标。它创建新的 `revisions/<revision-id>/`，不修改原文件：

- 保存根目录的制作文档与 JSON、`source/`、`assets/`、`audio/`。
- 保存当前 `run.json` 引用的候选视频、receipt、生产锁、封面、QA／审片目录和交接文件；保留来源底片及其交接资料。
- 保存 `output/` 顶层的 JSON、讲稿与字幕记录。其他人工审片证据可用重复的 `--include <项目内相对路径>` 显式补入。
- 保留联系图和原始审片索引；对应视频也已归档时，省略索引列出的独立逐帧图片。`archive-manifest.json.omittedDerived` 记录其路径、大小、字节摘要和所属索引。
- 不递归包含历史归档、`.cache/`、`.tmp/` 或不相关旧视频。没有自动删除、保留轮数淘汰或硬链接共享可变源文件的行为。

复制前后核对来源摘要，普通失败不发布半份归档。归档是历史证据，`resumable=false`；其记录保留原生产路径，不是可直接运行的搬迁项目。省略的图片需要从**该归档内对应的视频**按审片索引重新提取，不能误用原路径上后来覆盖的新视频。外部素材、字体和运行时仍需保留；恢复生产须先恢复相关输入，重新校验和审核。归档或重新抽图均不产生新的人工批准。

如果需要逐像素图像证据，另行显式保留原图并记录用途；不要将所有历史逐帧图默认为长期交付物，也不要用 `cp -R output` 代替选择当前版本。

## 只读审计与清理预览

归档被强制中断时，固定的 `revisions/.<revision-id>.pending/` 保留部分文件及状态记录；重试停止并要求先核对，不反复创建新的临时副本。普通异常会清理本次暂存目录。不要删除其他进程的锁或未经核对的中断目录。

```bash
npm run inspect:storage -- projects/<id>
npm run inspect:storage -- projects/<id> --duplicates --json
```

输出项目文件总字节、目录／扩展名分布和缓存候选；`--duplicates` 按文件长度预筛再流式计算 SHA-256，列出内容相同的文件组。命令不跟随项目内符号链接，不删除文件。逻辑重复字节不等于文件系统可释放的物理空间，重复文件也可能被多个版本引用。

`produce` 完成时在终端和 `run.storage` 汇报体积；达到 **256 MiB** 时明确提示检查。该提示线不是项目硬上限；长视频和较多源素材可能合理超过它。它不修改生产输入指纹、不取消原有 QA 或人工审核，也不授权自动删文件。

对已有膨胀项目，先审阅只读报告，再根据当前 `run.json`、交付需求及历史回退要求确定具体保留清单。旧 PNG、历史视频、缓存、付费生成素材和中断事务不能一起盲删；已有历史目录不会因为更新 Skill 自动变小。清理现有项目需要用户授权具体范围。
