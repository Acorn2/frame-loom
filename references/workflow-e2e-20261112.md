## 集成中修复的问题

第一处问题发生在镜头确认后。fast 校验将 generated 改为 validated，并按 Schema 顺序序列化 JSON。原预览指纹虽然归一化了状态，仍以 JSON 键顺序参与计算，将等价内容误判为变化。已改用项目现有的规范化内容哈希。复现中重建预校验输入后，其旧指纹与已确认预览完全一致；将状态统一后，前后规范化内容相同，原 JSON 序列化字符串不同。

第二处问题发生在恢复流程。已有 run 处于 failed 或 blocked 时，状态入口直接返回旧失败状态，盖住了后来生成的待确认镜头。状态入口现会核对反馈与预览证据。更新后的预览交给创作者；确认后交给 Agent 生产。如果生产或 QA 在这次确认之后失败，较新的失败记录仍优先显示。

新增回归覆盖 Schema 重新序列化、状态晋级、真实旁白修改使确认失效，以及失败后预览接手和后续 QA 失败的优先级。118 项相关测试通过，最后一次优先级调整又复测了 13 项相关测试。lint、类型检查及 diff 空白检查通过。
