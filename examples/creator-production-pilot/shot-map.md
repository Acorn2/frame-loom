# Claim → Shot Map

`C1`–`C4` 是内容主张，`opening` 等是 `storyboard.json` 中稳定的 scene ID。换素材或改文案时先更新本表，再只修改受影响的镜头；来源片段以 `source/source.md` 为准。

| Claim ID | 要表达的主张 | 来源位置与原文片段 | 复核状态 | Scene ID | 画面要完成的工作 | 文档衍生画面 |
| --- | --- | --- | --- | --- | --- | --- |
| C1 | FrameLoom 把已有材料转成可审阅、可重复渲染的视频 | S1：「它把 Markdown 或结构化内容转成经过人工审核、可重复渲染的 Remotion 视频。」 | 来源已对照；视觉方案待审 | `opening` | 大标题建立“材料到预览”的问题与结果 | 标题和注释 |
| C2 | 输入 Markdown 或结构化内容后，当前本地流程包含分镜、校验、渲染和 QA | S1：「它把 Markdown 或结构化内容转成经过人工审核、可重复渲染的 Remotion 视频。」；S2：`style selection → storyboard → validation → Remotion → silent/audio preview → QA report` | 来源已对照；视觉方案待审 | `process` | 三张步骤卡压缩呈现输入、执行、复核；不是软件操作录屏 | CSS 步骤纸卡 |
| C3 | fast 模式的自动预览不等于人工审核 | S3：「`fast` 不会把空白占位草稿写成视频，也不代表人工审核通过。」 | 来源已对照；视觉方案待审 | `claim` | 一句明确边界与补充说明 | 对比式主句与注释 |
| C4 | 自动检查后仍须完整播放复核 | S3：「自动检查通过仍需完整播放复核。」 | 来源已对照；视觉方案待审 | `closing` | 以行动结论结束，停留供阅读 | 结尾主句与停留 |
