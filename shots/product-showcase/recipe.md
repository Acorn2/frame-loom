# 产品实演 · product-showcase

正式受控配方，当前 experimental，仅验证 `studio-frame` × 16:9。版本由 catalog 固定；旧分镜不迁移。

先根据原文确定本场要解释的关系或操作，再编排 `slots.items` 与 `elements`。第一项完整显示 `scene.title`。文字、图解和字幕使用全片字体；示例文案不能写入 renderer。

## 输入要求

真实产品说明、有来源的本地截图，以及要展示的操作状态。截图须足够清晰；缺少实际界面或结果时先补充素材，不重画虚构界面。

## 运动制作方案

先展示界面上下文，再从同一张截图连续取景到关键区域。说明文字与取景错峰进入，先完成一个取景动作再开始下一个，最后停留供阅读。

保持截图比例，连续移动时避开标题与字幕。操作状态和结果来自真实截图；画面中的取景只解释所捕获的状态，不代表视频执行了实际操作。

## 生产契约

每个槽位绑定唯一图层和初始几何。图层只存内容；位置、取景和形状只在配方中声明。每项唯一 `reveal`；动作中点、完成态和切换前纳入生产 QA。

真实界面使用 `screenshot` 和有来源的本地图片，文字使用 `node`。至少一项媒体；不生成虚构 UI。`crop` 使用原图归一化坐标，必须完整位于原图内。每个 focus 绑定具体媒体、唯一 beat、目标框与取景；verticalDelay 可延后上移，避开标题。渲染读取图片真实尺寸并保持比例，完整展示所声明的取景区域。

## 边界

所有内容在 1920×1080 基准的 x=120..1800、y=96..850 内，给字幕保留空间。不得夹带隐藏状态或遗漏图层。正文按显式行分行，超出槽位应缩短或拆镜头。完成态至少保留 1.2 秒阅读时间。

本配方没有音效、语音或联网行为。配色采用现有项目配色契约。新文档的 Agent 编排仍须核对来源、关系、可读性与取景中间态；自动 QA 不替代完整播放。
