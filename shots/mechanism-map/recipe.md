# 机制图解 · mechanism-map

正式受控配方，当前 experimental，仅验证 `signal-noir` × 16:9。版本由 catalog 固定；旧分镜不迁移。

先根据原文确定本场要解释的关系或操作，再编排 `slots.items` 与 `elements`。第一项完整显示 `scene.title`。文字、图解和字幕使用全片字体；示例文案不能写入 renderer。

## 输入要求

有来源的流程、关系、状态与说明文字。先核对原文支持哪些连接；没有因果或循环依据时，不把普通关联画成因果路径或闭环。

## 运动制作方案

先建立本场要解释的问题，再按内容顺序展开分层结构、整体路径、时间轴或确认门。节点落定后才描画实际连接，需要强调时突出已有节点，最后保持完整结构供阅读。

在总览与局部之间保留定位线索。不同场景按解释任务选择构图，不必复制样片顺序，也不靠重复卡片延长镜头。

## 生产契约

每个槽位绑定唯一图层和初始几何。图层只存内容；位置、取景和形状只在配方中声明。每项唯一 `reveal`；动作中点、完成态和切换前纳入生产 QA。

机制使用 `node`，支持 text、panel、film、gate、plane。`composition` 标注 layers、route、timeline、gate 或 summary。每条实际关系放入 `scene.connections`，`routes` 只声明端点侧和可选折点；两端落定后执行一次 draw。必要节点可在落定后 highlight。不能用装饰连线捏造关系。

## 边界

所有内容在 1920×1080 基准的 x=120..1800、y=96..850 内，给字幕保留空间。不得夹带隐藏状态或遗漏图层。正文按显式行分行，超出槽位应缩短或拆镜头。完成态至少保留 1.2 秒阅读时间。

本配方没有音效、语音或联网行为。配色采用现有项目配色契约。新文档的 Agent 编排仍须核对来源、关系、可读性与取景中间态；自动 QA 不替代完整播放。
