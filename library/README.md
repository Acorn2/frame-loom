# 风格与镜头配方库

在仓库根目录运行 `npm run library`，打开命令打印的 `http://127.0.0.1:4318`。端口占用时使用 `npm run library -- --port 4319`。服务只监听本机，提供生成的公开页面与样例文件，不读取用户项目、不启动生产、不访问 TTS。

风格、镜头与导出分别使用独立静态页面，通过顶部导航和底部下一步入口切换：

- `index.html`：六套风格的较大预览、颜色示意与动态效果，选择一套风格、一个全片字体及制作画幅。
- `shots.html`：显示当前风格，按分类、名称或用途浏览与勾选兼容镜头，不展示风格卡片。
- `selection.html`：选择根据文档自动选镜头（默认）或手动集合，选择成品及配音，再复制制作指令。

切换组合会移除不兼容选择并提示；浏览器保存风格、画幅、已选镜头与公开制作选项；网页不填写或存储文档路径。浏览器禁用存储时通过页面 URL 参数携带风格、画幅、镜头 ID 与公开制作选项，仍可跨页选择，但不能自动恢复上次会话。详情预览播放位置也可保存在浏览器，播放中每两秒保存一次，暂停、关闭或离开页面时补存；重新打开样片可继续观看。

制作向导只要求选择最终用途：带旁白的视频，或仅画面供后期剪辑。带旁白时选择TTS或已有旁白；TTS可沿用本地已启用配置，或选择豆包/OpenAI/ElevenLabs/阿里百炼公开预设。模型与音色由仓库样例读取，预设不代表本机已启用。渲染前按[内容编排流程](../references/shot-planning.md)复查关键内容覆盖、重复构图和长停留。高级确认开关映射review/fast，但页面不要求理解这些参数。指令包含风格/镜头ID、交付用途、配音路由与配置选择，并要求缺少匹配配置时说明。文档与音频在Agent对话中提供，主题自动生成，网页不再导出仅初始化的命令。

风格与镜头的卡片、详情及复制指令不展示版本号。用户按名称和ID选择，Agent使用本地已注册的配方；内部生产契约继续负责兼容性与复现。

自动模式无需勾选镜头：Agent先读文档、查询兼容配方，记录逐场来源、画面表达与理由，再显式初始化选定集合。fast直接继续，review把组合与讲稿分镜一起审核。网页不读取文档或执行推荐。旧手动组合保持手动模式；手动集合为空时不能导出，只有标题镜头时展示适用范围提示。选择方式随存储及URL恢复；手动勾选镜头会切换到手动模式。

交接区在复制按钮前显示当前镜头选择方式；自动模式按钮为“复制自动编排指令”，手动模式为“复制指定镜头指令”并显示已选配方数量。两种指令均明确写入“镜头选择方式”，手动集合保留严格边界；制作前是否审核独立选择。切换后页面即时更新，已经复制到外部的旧文本需重新复制。

手动集合约束实际选用，不强制所有镜头出现，也不会自动加入未选基础配方。辅助动作与跨场转场只提供宿主、条件和预览，不进入 `--shots`。

## 真实预览

六套风格使用仓库的同分镜静音视频；标题、顺序图解和素材展示由各自的实际风格renderer生成，构图、中文字体、形状与入场方式均有区别。场景与附属能力来自 `examples/shot-recipes/` 的公开契约样例：

```bash
npm run preview:library
npm run library
```

首次生成需要 FFmpeg、可运行的 Remotion 浏览器和本机渲染时间。这只生成公开配方样片，输出在 Git 忽略的 `library/previews/`，不创建用户生产视频。页面启动前无需等待生成，样片缺失或过期时展示中性占位与明确状态，仍可查看说明和选择配方；生成结束后重新运行 `npm run library`，或运行 `npm run build:library` 并刷新正在打开的页面。

样片由实际 renderer 驱动，按原始画布排版后缩为 960×540；播放样片时使用原始速度。镜头样片覆盖六套当前风格的 16:9 横屏；卡片、详情与变体读取当前所选风格的实际样片。所有配方保持 experimental；样片播放不代表真实旁白、成片 QA 或人工交付批准。

`preview:library` 校验公开分镜、素材、安全区与文本布局后，复用一次打包生成 318 个样片（每套风格包含 37 场景、9 宿主动作、5 换章，加矩阵线框与卡堆胶带两个已支持变体，共 53 × 6）。完成态图片与样片来源写入 `library/previews/manifest.json`。源码、风格、配方或 fixture 改动会失效预览指纹，页面不再使用旧封面或旧动画，也不以历史fixture截图或其他配方画面替代；重新生成即可。生成失败保留此前完成的样片，后续运行继续补齐。

基础图解与收尾的公开样片包含“标记主张→留下出处→说明联系”的顺序图解和一个收尾标题：节点依次入场、连线展开、结论显示，卡片封面展示图解完成态。

镜头封面接近可见区域时才加载；桌面每次只自动静音循环播放一张最充分可见的卡片，离屏、页面隐藏或打开详情时暂停并取消视频加载。手机、省流量模式或系统启用“减少动态效果”时保留静态画面，通过详情或全屏按钮播放。卡片右上角支持全屏，点击画面或“配方说明”查看大图与做法；矩阵线框和卡堆胶带在详情中切换。实际播放与网页检查见[复核记录](../examples/shot-recipes/visual-review/README.md)。

## 数据与构建

- `scripts/lib/library-catalog.mjs` 从已注册的场景、辅助动作、转场 catalog 与 Style Pack index 读取真实能力；`catalog-labels.json` 仅提供中文呈现名称与分类。
- `scripts/lib/library-tts-catalog.mjs` 只从四份公开样例提取服务、模型、音色元数据，不读取projects、环境变量值或凭据；构建将其加入catalog。
- `selection.mjs` 负责兼容性、选择恢复与指令导出；不会读文章或编排生产分镜。
- 构建复用 Remotion 的浏览器，将实际 PNG 封面转换为同尺寸 WebP；原始封面不变，派生缓存位于 `.tmp/library-webp/`，内容指纹变化时重新转换。首次转换需要可运行的 Remotion 浏览器。
- `npm run build:library` 生成含三个 HTML 入口的 `dist/library/`，只复制页面、公开文案和样例媒体，可作为静态站点文件使用。每次启动会重新构建，避免 catalog 漂移。
- `npm run build:library -- --require-previews` 用于发布，要求六套风格、全部已注册配方及 30 组风格与字体组合都有有效的非空图片和动画。缺少当前指纹的预览时，在写入站点前失败；本地普通构建允许带明确待生成／待更新状态的中性占位。
- `scripts/serve-library.mjs` 只提供构建目录中的文件，支持视频 Range 请求；没有文件写入、生产 API 或项目目录入口。

搜索输入等待 150 毫秒后更新，中文输入组词期间不更新；按 Enter 或清空搜索立即更新，匹配结果与组合未变化时保留现有卡片和播放状态。

验证：`npm run test:library`、`npm run typecheck`、`npm run lint` 和 `npm run check:docs`。页面交互还需检查多选、切换兼容性、搜索、恢复、复制、样片播放及窄屏布局。

## GitHub Pages 发布

页面使用相对路径引用模块、`catalog.json` 和媒体，可部署在 GitHub 项目站点的 `/frame-loom/` 子路径；浏览器完成搜索、兼容性选择、存储和复制，运行时不需要 Node.js 服务。Pages 的 HTTPS 页面可以使用浏览器剪贴板接口，拒绝授权时仍可手动复制。

本仓库的 [Library Pages 工作流](../.github/workflows/library-pages.yml)按 [GitHub 官方 Actions 发布流程](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)构建站点：

1. `main` 上页面或依赖代码的 push、面向 `main` 的相关 PR，以及手动运行触发构建。手动发布选择 `main`；其他分支只构建。
2. Ubuntu 24.04 / Node.js 24 安装 FFmpeg、公开 Noto CJK 与 Liberation 字体，运行 `npm ci`、类型/lint/文档/配方校验和页面测试。
3. 分别按输入指纹恢复 `library/previews/` 和 `library/font-previews/` 缓存，再运行 `preview:library` 与 `preview:fonts` 补齐缺失样片。没有缓存时从公开样例完整生成，不依赖开发者机器上的文件。
4. 运行 `build:library -- --require-previews`，仅上传 `dist/library/` 为 Pages artifact。配方或字体组合样片不完整、站点构建失败时不会进入部署。
5. 仅 `main` 的非 PR 运行执行部署，使用 `github-pages` 环境。构建任务只有读取源码权限，Pages 与 OIDC 写权限只给部署任务；部署期间新的推送排队，不中断正在发布的版本。

首次使用，在 [仓库 Pages 设置](https://github.com/Acorn2/frame-loom/settings/pages)中将 **Source** 设为 **GitHub Actions**，提交并推送本轮页面及其依赖源码后运行工作流。默认站点地址为 [https://acorn2.github.io/frame-loom/](https://acorn2.github.io/frame-loom/)，实际发布结果以工作流 `deploy` 环境输出和 Pages 的 **Visit site** 为准。没有配置远端 Pages 或没有推送源码时，该地址不保证可访问。远端设置、推送和实际公开发布不是本地构建的一部分。

`dist/`、`library/previews/` 与 `library/font-previews/` 继续保持 Git 忽略，不需要提交 MP4 或改用专门的部署分支。发布源不能只选择原始 `library/` 目录，因为 catalog 和媒体由构建产生。`build:library` 也生成 `.nojekyll`，供使用其他静态发布方式时跳过 Jekyll；Actions 直接发布静态 artifact。

故障定位：

- `configure-pages` 找不到站点：核对仓库 Pages Source、账号计划及仓库权限。
- 发布构建提示预览缺失：检查之前的 `preview:library`、`preview:fonts` 渲染日志、字体与 FFmpeg；不要用普通构建绕过完整性检查。
- `deploy` 等待或被拒绝：核对 `github-pages` 环境的允许分支和人工批准要求。
- 页面正常但更新未出现：核对最新工作流的部署结果，刷新缓存；本地 127.0.0.1 的选择与线上站点的选择分别保存。

线上页面只展示公开样例并生成指令，不读取访问者的本地文档，不调用 TTS，也不替访问者在云端制作视频。

当前配方预览与实际生产使用同一套外观：全部37个场景配方使用白色、冷灰或石墨背景，辅助动作、转场与已支持变体继承宿主；不沿用米黄纸色。风格提供强调色与推荐字体，项目独立选择全片字体家族，镜头保留各自的构图、空间和动效。首屏优先展示不同构图，仍可按分类搜索与勾选；风格和镜头保持两个独立页面。

此前32份样片的中性底色及网页检查见[中性视觉复核](../examples/shot-recipes/neutral-visual-review/README.md)。

## 详情预览

网页同一时刻只播放一个预览：新视频开始播放时暂停其他视频；视频离屏或页面进入后台时暂停，返回后可手动继续播放。切换组合或详情变体、关闭详情时释放旧视频资源。镜头卡片返回可见区域时仍按自动预览规则播放。

详情弹窗采用桌面双栏：左侧实际样片、播放/暂停、进度、重播和全屏；右侧分为概览、制作要点与来源。概览先展示用途、动作和使用要求，制作要点保留配方的完整参数、声音建议及限制。手机纵向排列，标题、关闭和底部操作固定可见。场景可直接选择或取消，风格可直接使用，辅助动作和转场保留宿主条件、不加入场景集合；选择跨页保存。

标题旁的“复制镜头 ID”用于当前项目，无需复制完整说明；风格详情同样可复制风格 ID。“制作要点”中的“复制动效配方”用于其他项目，导出独立的输入、运动顺序、时长、参数、声音建议与来源，并可展开查看复制内容。完整项目说明仍保留。预览变体的复制范围为默认配方；辅助动作、转场仍按其宿主或章节条件使用。浏览器拒绝复制时提供已选中的文本供手动复制。

详情交互与实际检查见[视觉复核记录](../examples/shot-recipes/visual-review/README.md)。

## 风格卡片

风格页以中文名称、英文风格名、视觉特征和适用内容帮助选择。封面为同一实际公开样片4.5秒处的标题帧，保持完整16:9画面。电脑悬停或键盘聚焦停留 250 毫秒后预览，一次只播放一张；快速经过卡片不加载视频，移开时取消加载。手机点击进入完整样片。省流量模式或启用系统减少动态效果时不自动播放。

“可用镜头”按当前画幅与真实场景配方兼容性统计，不包含辅助动作与转场。只有基础语义配方的组合显示“1个基础镜头”。色点对应实际风格包的背景、文字和强调色，可悬停查看角色与颜色。

更新风格实现后，运行 `npm run preview:templates -- --output <new-directory>` 生成六套同分镜视频，复核后将视频与开篇／关系完成态复制到 examples/template-families/previews/ 的对应公开文件。运行 `npm run preview:library` 重建受影响的镜头样片，再运行 `node scripts/prepare-style-covers.mjs` 重建封面；静态构建检查封面记录与原样片哈希，失效时停止构建。封面资产与来源记录位于 `library/style-covers/`。

## 全片字体

风格页底部单选全片字体，标题、正文、图解和旁白字幕使用同一字体家族；字号、字重仍由镜头控制。墨白杂志推荐思源宋体，手绘便签推荐霞鹜文楷，其余推荐思源黑体。手动选择后切换风格保留字体，恢复推荐时重新跟随当前风格。字体和选择方式随公开组合跨页保存，也进入 URL 恢复及制作指令。

`npm run validate:fonts` 检查固定文件与许可指纹；`npm run preview:fonts` 生成 30 段横屏组合样片，再运行 `npm run library` 重建目录。字形卡片使用原字体裁剪的示例文件，组合样片使用正式 renderer 和完整字体；原风格／镜头样片标明原始字体。字体样片缺失或过期时提示，不用其他组合替代。

字体卡片使用从固定版本原字体裁剪的五份 WOFF2 示例文件，合计约 18 KB；当前选中字体优先加载，其他卡片进入视野或被选择时再加载。示例文字保存在 `library/font-samples/sample.txt`，可用安装了 `fonttools` 与 `brotli` 的隔离 Python 环境运行 `python3 scripts/generate-library-font-samples.py` 重新生成。构建会核对原字体与示例文件的 SHA-256 指纹。下方组合样片只先加载当前组合封面，点击播放后才请求视频。

静态构建复制 `fonts/font-index.json` 声明的公开字体及原始 OFL 文件，使用相对路径，兼容 GitHub Pages 项目子路径。无需系统安装或远程 CDN。本地普通构建可在字体组合样片缺失时显示明确提示；Pages 发布构建必须生成并校验全部组合样片。
